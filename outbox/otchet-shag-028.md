# Отчёт по шагу IMP-028 — опечатанный holdout

Пятый шаг Фазы 4.

## Что просили

План: «набор для финального гейта отделён от настроечного».

## Зачем это нужно

На настроечном наборе рецензента будут крутить — менять подсказку, пределы,
порядок проверок, — и всякая такая правка подгоняет его под виденное. Набор,
который рецензент не видел ни разу, — единственное, чем можно измерить его
настоящую способность. Пересекись части хоть одним случаем, и калибровка
покажет завышенную точность, а гейт пропустит негодного судью.

## Что получили

```
объединение   54 случая, положительных 44,4%, чужих 37,0%
holdout       18 случаев (33,3%), положительных 44,4%, чужих 38,9%
настроечная   36 случаев,          положительных 44,4%, чужих 36,1%
```

Отклонение долей меньше двух процентных пунктов при допуске в десять. Печать
поставлена: schema_version, метка времени, число случаев и отпечаток по парам
«имя, sha256». Снимается печать решением владельца на калибровочном гейте, а не
прибором и не арбитром.

Непересечение проверяется тремя способами: по пути, по имени и **по исходной
функции**. Третья — главная: один и тот же исходный код, попавший в обе части
под разными именами, не увидели бы первые две.

Прибор получил четыре входа: голая команда, настроечная часть, опечатанная,
объединение. Границы состава применяются только к объединению — часть, негодная
по числам в одиночку, годна в объединении, и в этом смысл разделения.

## Чем доказано

Живая проба арбитра шестью порчами копии:

```
чистая пара                    GOLDEN_OK
общий источник, разные имена   GOLDEN_PART_SOURCE_OVERLAP   код 19
печать подделана               GOLDEN_SEAL_BROKEN           код 16
печать снята                   GOLDEN_SEAL_MISSING          код 15
файл holdout изменён           GOLDEN_SEAL_BROKEN           код 16
метка из holdout в выводе      не появилась
```

Машинные факты: регрессия 96 из 96; мутации 455 из 455 убиты, ни выживших, ни
неприменившихся; спецификаций прибора 22, все убивают; датчик секретов чист;
приватная область публикации CF_PUBLISH_OK; набор прибора 59 случаев.

## Три находки, каждая нашлась измерением, а не чтением

**Первая: разделитель отказался резать корпус.** Имя функции в модуле не
уникально — методы разных классов дают одно имя, и два источника имели по
несколько случаев. Разрежь их по одному, часть случаев одного исходного кода
ушла бы в обе стороны. Делится группа источника целиком.

**Вторая: голая команда стала краснеть на исправном корпусе.** После разделения
она мерила настроечную часть границами объединения. Прибор, который кричит на
здоровом, отучает верить себе на больном — исправлено второй выдачей: голая
команда значит «объединение».

**Третья: в приборе оказались две реализации одной проверки.** Восемь
спецификаций мутаций, целящих в новую копию, выжили: случаи ходили через
старую. Сегодня копии совпадали; первая же правка одной создала бы прибор,
который на одном входе видит нарушение, а на другом нет. Устранено третьей
выдачей, дубль удалён, заведён страж единственности.

Ни одну из трёх не показал бы просмотр диффа. Первую нашёл отказ моего же
разделителя, вторую — прогон четырёх входов, третью — мутации.

## Что осталось неизвестным

Holdout не вскрывался ни разу: его содержимое проверено только отпечатками.
Так и задумано — вскрытие произойдёт на калибровочном гейте IMP-031 решением
владельца.

## Что это меняет для владельца

Появилась часть корпуса, которую рецензент не увидит до финального гейта.
Настройка на оставшихся 36 случаях больше не сможет незаметно улучшить
результат на 18 отложенных.
