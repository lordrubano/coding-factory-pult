# Отчёт по шагу IMP-024 — конфигурация рецензента

Первый шаг плана после закрытия ТЗ и первый, чей отчёт кладётся в ящик сразу.

## Что просили

План, Фаза 4: «`judge_config.json` с моделью и пределом; отсутствие даёт отказ».

## Что получили

Механизм чтения конфигурации существовал и раньше — четыре отказных кода в
`scripts/cf_judge.py`. Шаг достроил недостающее:

```
cf_judge.py config-check   проверка конфигурации без вызова рецензента,
                           шесть исходов, у каждого свой код возврата
страж единственности       машинная проверка PROP-016: личность рецензента
                           живёт в одном месте и больше нигде
```

При успехе печатаются модель и предел — **кто** судит и **сколько** ему дают
прочитать. При отказе не печатается ничего сверх исхода: умолчания модели не
существует.

## Чем проверено

Восемь входов прогнаны арбитром вживую, каждый дал названный исход:

```
файла нет                  JUDGE_CONFIG_UNAVAILABLE       код 2
годная конфигурация        JUDGE_CONFIG_OK + две величины код 0
чужая версия схемы         JUDGE_CONFIG_INVALID           код 3
не JSON                    JUDGE_CONFIG_INVALID           код 3
пустая модель              JUDGE_MODEL_MISSING            код 4
предел ноль                JUDGE_SIZE_LIMIT_MISSING       код 5
предел логический          JUDGE_SIZE_LIMIT_MISSING       код 5
негодный аргумент          JUDGE_CONFIG_USAGE             код 64
```

Машинные факты: регрессия 95 из 95; мутации 411 из 411 убиты, ни выживших, ни
неприменившихся; датчик секретов чист; набор судьи 17 -> 24 случая; спецификаций
на модуль судьи 20, все убивают.

Страж единственности доказывает собственную способность упасть внутри случая:
пять порч копии исходников — имя модели в файле маршрутизации, имя в диспетчере,
постоянная в судье, чтение из окружения, добывание из аргументов — и каждая его
роняет. Константы семейств `PRODUCER_FAMILY` и `VALIDATOR_FAMILY` его не роняют:
семейство и модель — разные вещи.

## Что осталось неизвестным

**Проверка «имени модели нет в файле маршрутизации» ищет одно конкретное имя.**
Другое имя, вписанное туда завтра, страж не заметит: структурные проверки этот
файл не покрывают. Сегодня он имён моделей не содержит вовсе. Устранение —
проверка «ни одного ключа, похожего на модель», отдельной работой.

**Файла конфигурации на диске нет, и он не создан этим шагом.** Значения —
имя модели и предел входа — по `PROP-016` ведёт владелец фабрики; исполнителю
путь `runtime/automation/judge_config.json` был закрыт заданием. Отсутствие файла
остаётся законным состоянием: рецензент отказывает всегда, `AD-29` не закрыт.

## Что это меняет для владельца

Конфигурацию рецензента теперь можно проверить одной командой, не запуская
рецензента и не тратя денег на вызов. До появления значений судья не вызывается
вовсе — и это устройство, а не недоделка.
